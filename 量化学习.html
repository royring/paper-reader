第一天 · 周六

基础与核心方法

① 上午 · 量化基础（3 小时）

学习目标：能手推仿射量化公式并算一个具体例子；能解释 LLM 量化的最大障碍——激活异常值；能画出 PTQ/QAT、W-only/W+A 的分类图。

1.1数值格式：从 FP16 到 INT4

格式位组成范围/特点用途
FP321 符号 + 8 指数 + 23 尾数范围极大、精度高训练传统模型
FP161 + 5 + 10范围小（max≈65504），易溢出推理基线
BF161 + 8 + 7范围同 FP32、精度低 → 训练更稳现代 LLM 训练/推理
INT88 位整数256 个台阶W8A8 权重/激活量化
INT44 位整数仅 16 个台阶 → 量化难度陡增W4A16 权重量化

量化本质：把连续浮点数映射到有限的整数台阶上。难点不在于"能不能表示"，而在于选哪些台阶、怎么分配 scale，才能让误差集中在模型不敏感的地方。

1.2仿射量化：核心公式（必须吃透）

量化：  x_q = round( x / s ) + z
反量化：  x̂ = ( x_q − z ) · s
scale：   s = ( x_max − x_min ) / ( 2^b − 1 )
零点：    z = − round( x_min / s )
  • 对称量化（z=0）：x_q = round(x/s)，s = max|x| / (2^(b−1) − 1)。适合权重——权重近似零均值、对称高斯分布。
  • 非对称量化（z≠0）：适合激活——ReLU 之后全部非负，分布明显偏一侧，硬用对称会浪费一半编码范围。
  • 粒度：per-tensor（整张张量一个 s）→ per-channel（权重每列一个 s，几乎标配）→ per-group/block（每 32/64/128 个连续元素一个 s，GGUF 和 bitsandbytes 的做法，对异常值最鲁棒，代价是存储更多元数据）。
✍️
手算例子（10 分钟）：设 b=8，张量 x = [−1.2, 0.4, 2.0]。非对称量化：s = (2.0−(−1.2))/255 ≈ 0.01255；z = −round(−1.2/0.01255) ≈ 96。于是 x_q = round(x/s)+z = [round(−95.6)+96, round(31.9)+96, round(159.4)+96] = [0, 128, 255]。反量化 x̂ = (x_q−z)·s = [−1.204, 0.4015, 1.993]。误差不超过 s/2 ≈ 0.0063 —— 这就是"量化台阶"的含义。再用对称模式（z=0）算一遍，观察 x_min 侧浪费了多少范围。

1.3量化分类：四个正交的维度

维度选项怎么选
何时量化PTQ（训练后）/ QAT（训练中）有校准数据、想省事 → PTQ；追求 <4bit 极限 → QAT
量化对象W-only（W4A16/W8A16）/ W+A（W8A8/W4A8）/ KV Cache显存不够、算力够 → W-only；GPU 服务器要吞吐 → W+A
scale 何时定静态（离线校准）/ 动态（运行时统计）激活分布难预测 → 动态；要极致性能 → 静态
粒度per-tensor / per-channel / per-block权重 per-channel 或 block；激活受硬件限制常为 per-tensor

1.4本领域最重要的一个事实：激活异常值

以 LLM.int8()（2022）的发现为起点：规模超过 ~6.7B 的模型，激活值中会出现系统性异常通道——幅度比普通值大 100 倍，且固定在同样几个 channel 上，贯穿所有层、所有 token。

⚠️
异常值为什么致命：per-tensor 的 s 被 max|x| 撑大 100 倍 → 普通 token 的所有值挤在不到 2 个整数台阶里 → 相当于把模型变成了 1-bit 精度 → 崩溃。而异常值本身又是模型下游 attention 用来"检索关键信息"的通道，不能直接截断。
🔑
全手册主线：GPTQ = 用后续权重补偿误差；AWQ = 缩放保护关键通道；SmoothQuant = 把难度从激活搬到权重；QuaRot/SpinQuant = 用旋转把异常值打散。全部招式都指向 §1.4 这一个问题。后面每学一个方法，问自己"它对异常值做了什么"。

② 下午 · 三大 PTQ 方法精讲（3 小时）

学习目标：对每个方法，能独立复述"优化什么目标函数 + 如何处理异常值 + 什么场景选它"，并能说出它量化的是 W 还是 A。

2.1共同框架：逐层重建（layer-wise reconstruction）

现代 PTQ 几乎都这样做：冻结其他层，对每一层（通常是每个 Transformer block）求解

minŴ  ‖ W X − Ŵ X‖²F ，  其中 Ŵ = Q(W)（量化后的权重）

其中 X 是一小批校准数据（~128 条文本）过该层的输入激活。关键洞察：不要求 Ŵ≈W，只要求输出尽量不变——这允许权重在"模型不敏感方向"上大幅移动。三个方法的区别就是用不同方式求解这个优化问题。

2.2GPTQ：逐列量化 + 误差补偿（读原文 §3，重点 3.3–3.4）

  • 来源：经典 OBQ/OBS（最优脑手术）——删除/量化一个权重后，为让输出误差最小，剩余权重应更新 δ = − w_q/s_q · (H⁻¹) 行向量。GPTQ 把它改造成可扩展到 LLM 的贪心逐列版本。
  • 算法：按列量化 W 的每一列 → 立即计算该列造成的输出误差 → 用尚未量化的后续列吸收这个误差 → 逐列推进。Hessian 用 H = 2XXᵀ 的 Cholesky 分解高效计算。
  • 异常值应对：只在权重侧（W4A16），激活不量化所以异常值暂时无害；对权重分布非常有效。
  • 实用特性：校准集与任务相关（域内数据更好）；支持把异常列（<1%）单独放高精度组（group size / act-order 选项）。实践中的 act_order=True（按激活重要度排序列）通常显著提升 INT4 精度。
  • 定位：GPU 服务端 4-bit 权重量化的事实标准之一，vLLM/ExLlama 原生支持。

2.3AWQ：保护 1% 关键通道（读原文 §3，重点图 2 的四分位实验）

  • 起点实验：把 0.5%–1% 的权重通道（按激活幅度选出的"显著通道"）保留 FP16，其余 INT4，精度几乎不掉 → 说明只有极少数通道是关键的。但混合精度对硬件不友好，AWQ 要找纯 INT4 方案。
  • 等价缩放技巧：给显著通道乘缩放 s（数学上等价于同步除到激活上，输出不变）：
    Y = (X)(W)ᵀ = (X · s⁻¹)(W · s)ᵀ，量化时用后者 → 权重通道被"放大" → 占用更多整数台阶 → 误差相对变小
  • s 怎么选：每通道网格搜索 α·s（约 20 个候选），s 初始 = 激活均值α（激活越大保护越强），取重建误差最小者。
  • 为什么优于朴素保护：GPTQ 的误差补偿对分布外数据可能失效；AWQ 的缩放改变的是量化网格本身，对域外泛化更稳（原文 Table：指令微调/数学/多模态模型上 AWQ 明显更稳）。
  • 定位：量化极快（分钟级）、部署面最广（TensorRT-LLM、vLLM、llama.cpp 都支持 AWQ 格式）。

2.4SmoothQuant：W8A8 的钥匙（读原文 §3，重点式 (3)(4)）

  • 核心观察：激活难量化（异常值）、权重好量化（无异常）→ 把异常值的"难度"按通道迁移给权重：
Y = (X)(W)ᵀ = ( X · diag(s)⁻¹ ) ( diag(s) · W )ᵀ
sj = α · max|Xj|α · max|Wj|1−α  （j 为通道下标；α 为迁移强度，逐层选，通常自动搜索）
  • 直观理解：激活大的通道除以 s（压平异常值），对应权重列乘 s（权重原本无异常，稍大也仍可量化）→ 两边都变得可量化。
  • 定位：真正的 W8A8 整数推理；是 TensorRT-LLM、MS-AMP 等"训练/推理一体化低精度栈"的基础。α 自动化版本见其开源实现（SmoothQuant/anomaly_adaptive）。
  • 局限：INT4 权重 + INT8 激活（W4A8）需要额外技巧（见前沿节 QuaRot 一脉）。

GPTQAWQSmoothQuant

异常值对策避开（不量化激活）缩放保护通道平滑进权重

③ 晚上 · QAT 与极低比特前沿（1.5–2 小时，可深可浅）

学习目标：理解伪量化与 STE 的前向/反向行为；知道 4bit 以下为什么必须换赛道（非均匀码本 / 旋转 / 从零训练）；对 2024–2025 前沿有地图感。

3.1QAT 原理：伪量化节点 + STE

在每个量化点（权重后、激活后）插入一个"假量化"算子：

前向：x → quant(x) → dequant(x)  （输出带量化噪声，模拟部署行为）
反向：梯度直通（Straight-Through Estimator）：∂/∂x [dequant(quant(x))] ≈ 1

即：前向传播吃量化误差，反向梯度假装量化不存在（round 不可导）。训练迫使权重移动到量化后也损失小的位置。LLM 全量 QAT 太贵，主流是 LoRA 式轻量 QAT（如 LLM-QAT：用模型自己生成的数据蒸馏 + 只训适配器）。

3.2极低比特三路线（<4bit）

路线代表核心思想（一段话讲清）
非均匀码本QTIP / QuIP#整数码本不一定是等距的 {0,1,2,…}：QTIP 用 E8 格码（Lattice）作为码本——格点分布接近高斯，权重正是高斯 → 同样 2bit 能表达的"典型值"更准。QuIP# 则结合随机旋转 + LDLQ 修正。
旋转打散异常值QuaRot / SpinQuant权重和激活同乘一个正交旋转矩阵（Hadamard，输出数学不变）：异常值被"摊薄"到所有通道 → 激活分布变均匀 → W4A4 / W4A8 全量化可行。SpinQuant 把旋转改为可学习，精度更进一步。
从零训练原生低精度BitNet b1.58权重 ∈ {−1,0,+1}（≈1.58bit），在训练中直接用三值前向（不是训练后压）。2025 年有工作研究 16-bit 预训练何时切换到 1.58-bit 持续预训练最划算（ACL 2025）。

3.3别忘了 KV Cache 量化

长上下文时 KV Cache 显存 = 2 × layers × heads × head_dim × seq_len × bytes，很容易超过权重本身。KIVI 把 K 压到 per-channel 2bit、V 保持 per-token，精度基本不掉；KVQuant（arXiv 2401.18027）进一步到 2-bit 全 KV。部署长上下文模型前必看。

3.4训练侧与硬件侧（了解即可）

  • FP8 训练：Transformer Engine / MS-AMP——量化不只发生在推理端。
  • 内核协同设计：如 LiquidGEMM（W4A8 内核, 2025）——量化算法必须与 GEMM 内核形态匹配才有真实吞吐。
  • 混合精度自动搜索：逐层选 bit 的 MPQ 方向，2025 综述见 arXiv 2510.16805。

4.1llama.cpp + GGUF（必做，门槛最低）

概念：GGUF 是 llama.cpp 的单文件容器；命名如 Q4_K_M：Q=量化位数，K=K-quant 分块方案（k-quants 论文 arXiv 2306.14425），M=medium（尺寸/精度折中）。另有 IQ4_XS 等 i-quant（重要性矩阵加权，低比特更准）。

git clone https://github.com/ggml-org/llama.cpp && cd llama.cpp
cmake -B build && cmake --build build -j            # 纯 CPU 即可

# 下载现成 GGUF（HuggingFace 搜 "Qwen2.5-1.5B-Instruct-GGUF Q4_K_M"）后：
./build/bin/llama-cli  -m model.Q4_K_M.gguf -p "用一句话解释量化" -n 200
./build/bin/llama-perplexity -m model.Q4_K_M.gguf -f wiki.test.raw   # 困惑度

自己转换：python convert_hf_to_gguf.py <HF模型目录> 得到 F16 GGUF，再 ./llama-quantize in.gguf out.Q4_K_M.gguf Q4_K_M。

值得知道：Unsloth Dynamic GGUF 按层敏感度动态混 4/5/6bit，同尺寸精度更好，HF 上搜 -UD 后缀（如 DeepSeek-R1-GGUF-UD）。

4.2GPTQModel（必做之一：自己量化一个模型）

GPTQModel：GPTQ 的活跃维护实现（取代 AutoGPTQ），兼容 vLLM 部署。

pip install gptqmodel
# 一行量化（自动下载校准）：
gptqmodel Qwen/Qwen2.5-1.5B-Instruct --bits 4 --group_size 128 --output_dir ./qwen-int4-gptq
# 或 Python API：
# from gptqmodel import GptqModel
# m = GptqModel.load("./qwen-int4-gptq")  # 直接推理验证

关键参数直觉：bits 精度主档位；group_size 越小越准、文件越大（128 是常用平衡）；act_order=True 通常免费涨点。

4.3vLLM（GPU 用户必做：生产级服务）

vLLM：高吞吐推理引擎，原生加载 GPTQ/AWQ/FP8 模型，一条命令起 OpenAI 兼容 API。

pip install vllm
vllm serve Qwen/Qwen2.5-1.5B-Instruct-GPTQ-Int4 --quantization gptq
# 另一终端（或直接 curl）：
# from openai import OpenAI; ... base_url="http://localhost:8000/v1"

延伸：vLLM 团队的新量化工具 llm-compressor（GPTQ/AWQ/FP8 一站式，产出直接被 vLLM 加载），正在取代旧流程，值得提前上手。
