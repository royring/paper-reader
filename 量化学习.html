第一天 · 周六

基础与核心方法

上午 · 量化基础（约 3 小时）

1.1为什么需要量化？

  • 大模型参数以 FP16 / BF16 存储，7B 模型仅权重就需 ~14 GB 显存。
  • 量化（Quantization）= 用更少比特表示权重 / 激活值（如 INT8、INT4），收益：
    • 显存 / 内存降为 1/2 ~ 1/8
    • 推理更快（低精度 GEMM 算子吞吐更高，如 W4A8、W4A4）
    • 能耗更低，是可持续 AI 优化的重要一环（见 神经网络优化综述）
  • 代价：数值精度损失 → 掉点。量化研究的核心就是如何少掉点甚至不掉点。

1.2核心数学：线性量化

最常见的均匀仿射量化（uniform affine quantization）：

x_q = round(x / s) + z          # 量化
x̂  = (x_q - z) * s              # 反量化（dequantize）
s  = (x_max - x_min) / (2^b - 1) # scale（缩放因子）
z  = -round(x_min / s)           # zero point（零点）
对称量化
z = 0，适合权重（近似零均值高斯分布）
非对称量化
z ≠ 0，适合激活值（如 ReLU 后全非负、有偏移）
逐通道 vs 逐张量
权重几乎总是 per-channel；激活一般 per-tensor（硬件友好）
分块量化（Block-wise）：每 64/128 个连续元素共享一组 (scale, min)，是 GGUF / bitsandbytes 的做法，对异常值更鲁棒。
✍️
动手练习（30 分钟）：用 NumPy 手写 quantize_int8(x, asymmetric=True) 和 dequantize，量化随机张量并计算 MSE 与余弦相似度，观察对称 vs 非对称在 ReLU 输出上的差异。

1.3量化分类（一张图记住）

                 ┌─ 训练后量化 PTQ（无需重训练，校准数据即可）
量化时机 ─────────┤
                 └─ 量化感知训练 QAT（训练/微调中模拟量化）

                 ┌─ 仅权重 W-only（INT4 权重 + FP16 激活）
量化对象 ─────────┤
                 └─ 权重+激活 W+A（W4A16 / W8A8 / W4A8 / W4A4）

                 ┌─ 静态：离线确定激活 scale
激活 scale ───────┤
                 └─ 动态：运行时实时统计（KV Cache 也可量化）
  • PTQ vs QAT：PTQ 便宜、主流；QAT 精度上限更高，极低比特（<4bit）必需。相关应用综述见 ACM QAT 应用综述。
  • KV Cache 量化：长上下文场景下 KV Cache 显存占用超过权重，量化它是关键优化点。

1.4为什么 LLM 量化难？—— 异常值（Outliers）问题

⚠️
LLM 激活值中存在系统性大幅异常值（比正常值大 100 倍），集中在特定通道，贯穿几乎所有层。若用统一 scale，异常值会"撑大"scale，把正常值挤进很少的量化台阶 → 精度崩塌。
🔑
几乎所有现代量化方法都在解决这一个问题。记住这句话，下午的方法全部能串起来。

2.2三大必学方法（每个 45 分钟）

① GPTQ必学
2022 · ICLR'23
基于二阶信息的逐列量化。把逐层量化视为最小化层输出重建误差 ‖Wx − Q(W)x‖² 的优化问题，利用 Hessian 近似（X = XXᵀ），逐列量化并用后续列补偿误差（源自经典 OBS/OBQ）。

权重 INT4 + 激活 FP16；对校准集敏感；是 vLLM / ExLlama 等 4-bit 推理的基础。现代实现见 GPTQModel。
② AWQ必学
2023 · MLSys'24
激活感知的缩放。并非所有权重通道同等重要——保护极少数（~1%）"显著通道"（由激活幅度识别）即可保住精度；为这些通道乘上 per-channel 缩放 s，等价于改变量化网格分布，无需混合精度、无需重训练。

量化速度快、跨模态/领域泛化好；工业界部署最广泛的方法之一。
③ SmoothQuant必学
2022 · ICLR'23
难度从激活迁移到权重。数学等价变换：激活异常通道除以 s，对应权重列乘以 s —— 异常值被"平滑"进权重（权重比激活好量化得多），从而实现 W8A8 全量化。

真正的权重+激活整数量化，是 TensorRT-LLM、MS-AMP 等高速推理的关键。
🧠
串联记忆：GPTQ 用"误差补偿"对付权重量化；AWQ 用"通道保护"对付权重量化；SmoothQuant 用"难度迁移"同时搞定权重和激活。三者都源于 §1.4 的异常值问题。

2.3其他值得知道的方法（各 10 分钟）

  • OmniQuant：可学习的等效变换（scale / clip 参数），统一框架。
  • HQQ / QQQ：免校准数据的快速 4bit 量化，速度极快。
  • QuaRot / SpinQuant（2024, Meta）：用旋转矩阵（Hadamard / 学习到的旋转）把异常值"打散"到所有通道，激活分布更均匀，从而支持 W4A4 甚至更低，是当前研究主线之一。
  • GSQ 等新方法（2025）：面向极低位标量量化（W2/W3）的高精度方案，见 相关介绍。
✍️
下午练习：阅读三篇方法的摘要与图 1（各 ~15 分钟），在白纸上画出三种方法分别"动了什么"（权重列缩放？Hessian 补偿？激活平滑？）。

晚上 · QAT 与极低比特前沿（约 1.5–2 小时，可选深度）

3.1QAT（Quantization-Aware Training）

  • 原理：前向传播中插入"伪量化"（fake quantize：量化 → 反量化，STE 直通梯度反向传播），让模型在训练中适应量化噪声。
  • LLM 场景：全量 QAT 太贵，主流是 QAT-LoRA 微调（只训 LoRA 适配器）；BRECQ / AdaRound 的思想也被移植到 LLM。
  • 选择准则：≥4bit 用 PTQ 即可；≤3bit 或 W4A4 以下基本必须 QAT。

3.2极低比特与前沿方向（了解即可，2024–2025）

方向代表工作一句话
1.58-bit（三值）BitNet b1.58（微软, 2024）权重只有 {−1, 0, +1}，需从零预训练（不是 PTQ）；最新研究探索 16→1.58-bit 持续预训练时机（ACL 2025）
非均匀量化QTIP / QuIP#用格码（lattice codebook，E8 等）替代均匀网格，2bit 精度显著优于 GPTQ/AWQ
旋转不变性QuaRot / SpinQuant / DuQuantHadamard 旋转打散异常值，实现 W4A4
混合精度搜索MPQ 系列（2025 综述）逐层/逐模块自动决定谁用几 bit
KV Cache 量化KIVI / KVQuant2bit KV Cache，长上下文必读
训练中量化MS-AMP（TE + QAT）训练 / 微调本身的低精度化
新硬件内核LiquidGEMM（2025）W4A8 高性能服务内核

工具链实战与端到端部署

上午 · 四大常用工具（约 3 小时）

🛠️
建议环境：Linux / WSL2 + conda，GPU 显存 ≥ 12GB 更佳（纯 CPU 也可走 GGUF 路线）。

4.1GPTQModel —— 训练后量化工具箱（1 小时）

ModelTC/gptqmodel：活跃维护，支持 GPTQ / AWQ / HQQ 等多算法，兼容 vLLM，取代 AutoGPTQ。

$ pip install gptqmodel
from gptqmodel import GptqModel
from transformers import AutoTokenizer

model = GptqModel.load("./Qwen2.5-1.5B-gptq-int4")   # 从 HF 下载已量化模型
tok = AutoTokenizer.from_pretrained("./Qwen2.5-1.5B-gptq-int4")
print(model.generate(tok("量化是什么？", return_tensors="pt").input_ids.cuda()))

也可自己量化：GptqModel.from_pretrained(fp16_model_path, quant_config) 一行完成校准 + 量化。

4.2llama.cpp / GGUF —— CPU 与边缘部署之王（1 小时）

  • GGUF：llama.cpp 的模型容器格式，支持 Q8_0 / Q6_K / Q4_K_M / IQ4_XS 等多种 K-quant 与 i-quant（重要性矩阵加权的低比特）。
  • Unsloth Dynamic GGUF：按层动态选择 4/5/6bit（敏感层保留更高精度），同尺寸下精度显著优于静态 Q4_K_M，见 Unsloth Dynamic 2.0 发布；可直接下载如 unsloth/DeepSeek-R1-GGUF-UD。
$ git clone https://github.com/ggml-org/llama.cpp && cd llama.cpp
cmake -B build && cmake --build build -j        # 纯 CPU 即可
# 下载一个 Q4_K_M GGUF 后：
./build/bin/llama-cli -m model.Q4_K_M.gguf -p "你好，量化世界" -n 128

4.3vLLM —— 高吞吐服务端（45 分钟）

生产部署标准选择；原生支持 GPTQ / AWQ / FP8 / INT8，融合内核（fused MoE、量化 attention），多 GPU 张量并行。

$ pip install vllm
vllm serve Qwen/Qwen2.5-1.5B-Instruct-GPTQ-Int4 \
    --quantization gptq --dtype float16

用 curl 或 openai SDK 请求，对比 FP16 版本的吞吐与显存。

4.4bitsandbytes + 其他生态（15 分钟）

  • bitsandbytes：load_in_4bit/8bit 一行加载，NF4 分块量化；QLoRA 微调的底座。
  • MS-AMP / Transformer Engine：训练侧低精度（FP8）。
  • TensorRT-LLM / MindSpore Lite：内置 SmoothQuant 等方案的推理引擎。
